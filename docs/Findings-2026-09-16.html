1. What was built

0.8.0 — Fence: secrets that reached a transcript built · tested · delivered

glassbox fence [ID|FILE|DIR] [--since] [--project] [--format text|md|json] [--out] [--fail-on error|warn|info] [--shred]. Scans Claude Code transcripts for credentials by format (AWS, GitHub, Anthropic, OpenAI, Slack, Stripe, Google, npm, SendGrid, private-key blocks, database URLs with passwords — error), secrets by context (password=, api_key:, Bearer, basic-auth URLs, JWTs — warn) and credential-file reads (.env, .npmrc, .netrc, id_rsa, *.pem, secrets.json — info). Every row is a masked preview and an 8-hex SHA-256 fingerprint, never the value; the same key can be recognised across sessions without the report carrying it. --shred overwrites each value in place with [FENCED:rule:fingerprint]: no backup, every rewritten line re-parsed before anything is written, atomic rename, CRLF preserved. A shredded transcript still opens and checks.

Engineering: DESIGN.md §14, nine tests written before the code, 111 total, e2e and audit green. Docs: FENCE.md, IT.md §6b, PILOT.md day-0 sweep, README, CHANGELOG.

0.9.0 — Adhere: "is my CLAUDE.md doing anything?" built · tested · delivered

glassbox adhere [--project DIR] [--claude-md FILE] [--since] [--format] [--out] [--redact] [--fail-under N]. Reads the project's instruction files (CLAUDE.md, .claude/CLAUDE.md, CLAUDE.local.md, ~/.claude/CLAUDE.md), turns each line into a rule, finds every session of that project, and judges each rule per occasion with evidence (session, turn prompt, command or path). Nine shapes are checkable mechanically: run X before commit/push, run X after changes, use A not B, never run, never touch, ask before, read before edit, commit message format, no new docs. Everything else is listed as not checkable yet with its line number, so the report never claims more than it measured. Headline: N rules · K checkable · sessions · obeyed X of Y occasions (Z%).

Engineering: DESIGN.md §15, ten tests before the code, 121 total, e2e and audit green. Docs: ADHERE.md, IT.md §6c, README, CHANGELOG.

2. What the real runs found

Fence, run on the session that built it

1.2 MB, one transcript. 50 findings, 19 distinct secrets — every one of them a planted test value that had passed through tool inputs and outputs while the tests were being written. --shred on a copy rewrote 96 occurrences; all 221 lines still parsed and glassbox check gave the same result. On the real fixture transcript (test/fixtures/real-main.jsonl): nothing found, which is the correct answer for that file. The point for the launch post: the tool's own build session is proof that a transcript collects everything the agent touches, including secrets it was only shown in passing.

Adhere, run on the session that built it

Against a CLAUDE.md written for the test with the rules Glassbox would plausibly have, the score was 22% — 12 of 54 occasions.

The reading: the rules that were obeyed are the ones that cost nothing to obey (don't touch dist, don't force push). The ones ignored are habits — grep over rg 38 times in one session — and the ones where the instruction was never in the prompt at the moment of the action (the one commit was requested by a Stop hook, not by you, and its message was v0.8.0: glassbox fence — …, not feat:). That is the honest shape of the answer to "is my CLAUDE.md doing anything?": the cheap rules, yes; the habit-changing rules, much less; and you can now see which is which.

Three bugs the first run found in the tool itself

The first pass of the same run scored 19% and was wrong in both directions. A git push --force inside a document being written with a heredoc was counted as a force push (3 breaches). Commits inside node -e "…" test strings were counted as commits (5 instead of 1). The one real commit was missed entirely because it read git -c user.name=… commit. All three are fixed by judging commands on their shell surface — heredoc bodies and inline programs are content, segments split on && | ; and newlines, git's leading options looked through — and all three are now tests. This is exactly what the "run it on a real transcript before calling it done" rule is for.

5. One thing worth keeping

Both tools were only right after they were run on a real transcript. The tests passed before that; the real run is what found the heredoc, the inline program and the git -c case. "Ship nothing that hasn't been run on the session that built it" is a rule now — and, yes, it is checkable.
