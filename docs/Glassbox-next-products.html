Glassbox — the next products

The list from 16 September 2026. What each one is, why Claude's own system would be better for it, why it is worth Aldo's time, and how big it is. Written by Claude for Aldo Hushi, BlueprintAU, Adelaide.

On 5 September the brief was "go wild — build a tool Claude's own system would benefit from and that gets you noticed". Four things were on the table: an Agent Trace Viewer, a Skill Linter, a Memory Auditor and Session Receipts. The viewer became Glassbox and is at 0.8.0 eleven days later. This is the rest of that list, plus the ideas that only became visible once Glassbox existed. Every one of them rides on code Glassbox already has, and every one answers a question an IT department asks before it buys.

The original list, revisited

Session Receipts absorbed into Glassbox

Where it went: check --rates, the cost summary, the Stop hook's one-screen summary, the audit report generator.

The idea was a receipt at the end of every session — what it cost, what it did, what went wrong. That is exactly what the Stop hook prints and what the audit report is built from. Nothing left to build as a separate thing.

Memory Auditor open — small build

Two to three days. Reuses Glassbox's file scanning and the audit report generator.

What. Reads a project's CLAUDE.md files, the user's memory directory and any .glassbox/last-session.md, and reports stale lines ("uses Postgres" beside "moved to SQLite"), duplicates across files, instructions that contradict each other, lines that reference files or commands that no longer exist, and the token tax the whole set adds to every session before the first word is typed.

Why Claude is better for it. Memory and CLAUDE.md are loaded into every session and nobody prunes them. Every stale line is a small chance the model follows it confidently and does the wrong thing. A clean memory is a more predictable agent.

Why Aldo. It is a natural section of the paid audit: "your team's CLAUDE.md files cost $X a month to load and a third of the lines are dead". It reads a folder; it never needs a transcript.

Skill Linter partly overtaken — fold into Adherence

Anthropic has since shipped skill-creator and /skill-doctor, which cover the static checks: description quality, trigger words, length, structure.

What they do not do is the thing Glassbox is uniquely placed for: measuring from transcripts whether a skill actually fires when it should, and what it costs when it does. That is a rule inside Adherence (below), not a product of its own.

The new ideas

Fence — secrets in transcripts built today · v0.8.0

Shipped 16 Sep 2026: glassbox fence [ID|FILE|DIR] [--since] [--format] [--out] [--fail-on] [--shred]. 9 tests, e2e and audit green; verified on the transcript of the session that built it (50 findings — the planted test values — 96 values shredded, every line still parses).

What. Every Claude Code session is a plain-text file under ~/.claude/projects, and everything the agent read is in it — the .env it opened, the token git remote -v printed, the key the user pasted. Those files never expire, sync wherever the home folder syncs, and get attached to bug reports. Fence scans them for credentials by format (AWS, GitHub, Anthropic, OpenAI, Slack, Stripe, Google, npm, SendGrid, private keys, database URLs with passwords), secrets by context (password=, api_key:, Bearer, basic-auth URLs, JWTs) and credential-file reads (.env, .npmrc, id_rsa, *.pem …). Each row is a masked preview and a fingerprint, never the value. --shred overwrites the value in place with [FENCED:rule:fingerprint]; a shredded transcript still opens and checks.

Why Claude is better for it. A transcript that leaks a key is a reason for a company to switch the agent off. Making the artefact the agent leaves behind safe to keep is part of making the agent safe to run.

Why Aldo. For a 100-seat IT department this is the scariest slide in the pilot deck and the one that gets Glassbox bought: "does it work?" is the audit; "is it safe?" is Fence. It is also the first thing in the toolchain that looks back at those files at all.

Adherence — a CLAUDE.md compliance report next — the one nobody has

Two to three days for the first rule pack. A Glassbox rule pack plus a small parser for CLAUDE.md, not a new product.

What. Cross-reference every rule in a project's CLAUDE.md against thirty sessions of transcripts and report which rules the agent obeyed, which it ignored, and what ignoring them cost: "'run tests before committing' — skipped in 11 of 14 sessions that committed", "'use pnpm' — npm was run 23 times", "'never touch migrations/' — edited twice". The first version handles the rule shapes that are mechanically checkable (run X before Y, use tool A not B, never touch path P, always read before edit, ask before Z) and lists the rest as "not checkable yet". Skills get the same treatment: did the skill fire on the prompts it should have, and what did it cost when it did.

Why Claude is better for it. It is the first honest answer to "is my CLAUDE.md doing anything?" — and a measured list of the instructions the model drops is the most useful feedback a model team could be handed. It closes the loop the Stop hook opened.

Why Aldo. Nobody has this. It is the demo that makes a room of engineers lean in, and it is the audit's headline finding for any team that has written a CLAUDE.md and wondered.

Startup tax — the cold-open analyser next — one day

One rule in check plus a table in collect. Transcripts already carry the first request's cache-write size.

What. Before the first prompt a session loads CLAUDE.md, skills, memory and every MCP tool schema. Measure that fixed cost per session and per fleet, rank the contributors, and pair it with the one recommendation a customer can act on the same afternoon: "the Gmail MCP costs 4k tokens on every session and was used in 2 of 40 — defer it". Fleet-wide through collect.

Why Claude is better for it. Fewer bloated prompts means more of the context window for the work and fewer compactions.

Why Aldo. It is the cost-audit finding with the shortest path from report to saving.

Approvals — a permission-friction report later — two days

Glassbox already parses permission-denied events; this is the other side of them.

What. Mine transcripts for what the user keeps approving by hand and propose the allowlist rules that would stop the prompts; and the reverse — the denials that show something the agent keeps trying to do and shouldn't, which belong in CLAUDE.md as a rule.

Why Claude is better for it. Less friction for the user, fewer sessions stalled at a prompt nobody is there to answer.

Why Aldo. A small, concrete deliverable for the workshop tier: a settings.json diff the team can adopt in ten minutes.

Replay — a regression harness for the configuration layer back pocket — months

A real engineering project. Needs the Agent SDK, a sandbox per replay, and a way to diff two runs.

What. Take a recorded session, change one thing — a CLAUDE.md line, a skill, a hook, the model — and re-run the same prompts to see what the agent does differently. Diff the two runs with compare. Nobody tests their CLAUDE.md today; this makes it testable.

Why Claude is better for it. It turns "we changed the instructions and hope it helped" into an experiment with a result.

Why Aldo. This is the one Anthropic itself would notice, and the one to build once Glassbox has a customer paying for it — it is the only item on this list that costs tokens to run.
