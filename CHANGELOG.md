### The road to 90
**The road to 90.** A Claude Code session on someone else's Mac ran Glassbox over its own transcripts and scored it 78/100: real findings, local, no tokens, a claims check you can't get any other way, and keys found in transcripts nobody knew were there. It took marks off for four things, and named the fixes: "stream large files, cap the key-block rule, make the 'next time' advice land in the agent's own memory," and put the loop guard in the plugin. This release is those four, test-first. DESIGN.md §21.
- **Transcripts of any size.** A 1.26 GB session broke `check` outright: the file was read into one string, and Node can't hold more than ~512 MB in one (`ERR_STRING_TOO_LONG`). Files over 64 MB are now read line by line (`src/jsonl.mjs`); smaller ones exactly as before. Fixing that showed the next wall: holding every multi-MB tool result of a 2.7 GB session ran Node out of heap. On the line-by-line path, a string over 64 KB is kept as its first and last 32 KB with a marker carrying its true size, so every size in the report is still exact; parsed records are copied so a short value kept from a long line doesn't pin the line. A synthetic 2.7 GB session — 323 reads of 4 MB, a planted token, three failing test runs and an "all tests pass" — now checks in about 10 seconds with ~110 MB of heap: oversized reads at their real size (largest 4,194,351 chars), the retry loop, the contradicted claim. `claims` looks for a number in each result instead of one joined string (the joined string hit the same limit). `fence` scans a big transcript in 32 MB segments of whole lines with the tool-call map carried across, so the findings, line numbers, fingerprints and attribution match a whole-file scan, and `--shred` rewrites it segment by segment with the same checks and a rename at the end. `list --grep` and `recall` work on big files. `open` says the file is too large for the browser viewer and points to `check`, instead of failing. A single line past the string limit is skipped and reported, not fatal.
- **A private key has to be a key.** The `private-key` rule matched from a BEGIN marker to the next END marker however far apart they were: a session that read docs mentioning both became a 20-million-character "key". The body is now at most 16,384 characters, can't contain another marker, and must be base64 once its header lines (`Proc-Type:`, `DEK-Info:`, `Comment:`, `Version:`) and line breaks — real or JSON-escaped — are removed. Real keys, encrypted PEMs included, are still found whole; a key after a stray marker is still found.
- **One memory.** With `--context`, the lessons that keep coming back now go into the agent's own memory instead of a second one beside it: one block in auto memory's `MEMORY.md` (under its title, inside the 200 lines that load) when auto memory is on, else in `CLAUDE.local.md`, never `CLAUDE.md`. The block is rebuilt from the ledger at every Stop — at most five lessons with their "next time" line, ~1,800 characters, secrets masked — and removed when none is active. Nothing outside its markers is touched; CRLF stays CRLF; a start marker whose end was deleted replaces only its own line. The SessionStart hook says nothing in this mode. *Told* now comes from the keys in the block's end marker at a session's first Stop. `--memory glassbox` (plugin option `memory`) keeps 0.11's note. `glassbox memory` shows the block and its file; `memory clear` removes it. `hook install --context` registers only the Stop hook now.
- **The loop guard is in the plugin.** `hooks/glassbox-guard.mjs`, a PreToolUse hook that imports the guard alone (no CLI), on by default (plugin option `guard`, or `GLASSBOX_GUARD=false`). It runs before Bash and PowerShell commands only: a plugin's hooks run for every plugin user, a Node start costs ~30 ms here and up to a second on some Windows machines, and identical failing retries are commands — so reads and edits never wait on it. It steps aside when `settings.json` already has a Glassbox `--guard` hook. The CLI's `--guard` still covers every tool.
- **Found in an independent review before release**, two rounds, every item now a test. Blockers: the block writer took a marker quoted in prose, inline code or a fenced example for the block and deleted the user's lines around it — markers now count only as whole lines outside CommonMark fences (closer as long as its opener, no info string; an unclosed fence is rescanned so blocks can't multiply), and extra blocks are dropped; two Stops writing at once could empty the file through a shared temp name — each writer now has its own (`wx`); a password in a repeated `echo <pw> \| sudo -S …` reached the lesson key and so the agent's memory — `commandHead` skips segments that only feed data (`echo`, `printf`, `yes`, `cat <<`), drops leftover `sudo` options and won't keep a word that looks like a secret, while names like `build:es2015`, `python3.11`, `webpack5` stay; the base64 check missed real keys read through the Read tool or `cat -n` (line-number prefixes) and keys inside a `service-account.json` (`\\n` in JSONL) — 34 of 34 generated key cases are found now. Should-fix: symlinked memory files are written through the link (a dangling link is left alone), the file's mode is kept, a read-only file is skipped; a key, title or path can't forge an end marker (`<!--` is broken in block lines); a BOM stays first; the size marker carries a per-process nonce (a planted marker in a web page read a 40-character result as 900 million) and a hash of the cut part (three different 300 KB writes sharing a head and tail read as a retry loop); a number in a cut result counts as found, and a test claim whose run was cut with no counts left is `unverified`, not `verified`; a credential file read twice stopped `--shred` (an empty span, in 0.11 too); the guard ignores only `description` now — a longer `timeout` or a background run after timeouts is a real change, so it is not blocked; a JSON array after a long run of blanks is read as an array.
- Tests: `test/jsonl.test.mjs` (15, one of them a 600 MB transcript behind `GLASSBOX_HEAVY=1`), `fence.test.mjs` +5, `memory.test.mjs` +13, `plugin.test.mjs` +3, `guard.test.mjs` (one rewritten); the 0.11 memory tests now run with `--memory glassbox`. 239 tests.

### `glassbox plan`: what a Pro/Max plan carried (built locally as "0.11.0")
**`glassbox plan`: what a Pro/Max plan carried.** It reads the plan from `~/.claude.json`, two fields only: `oauthAccount.organizationRateLimitTier` (e.g. `default_claude_max_20x`) and `subscriptionCreatedAt`. Then it prices every request at list price **by its own timestamp** and reports:
- each billing month (anchored on the subscription's day and time of day, so a 31st falls on a short month's last day) against the plan price, with the multiple
- the last 7 days by model
- 5-hour windows, rebuilt the way ccusage `blocks` does it (a window opens at the first request after the last one closed), heaviest first, with the session that used most of each and the open window marked `now`
- limit hits: the synthetic `isApiErrorMessage` record Claude Code writes in place of a reply. *Plan limit* means limit text or `billing_error`; *rate limited* means a plain `rate_limit`.

Requests are counted once across sessions (a resumed session repeats earlier `requestId`s), and `<synthetic>` replies aren't requests. Flags: `--since` (windows and hits; default 7d), `--plan pro|max-5x|max-20x|none`, `--plan-price N` (the default is the USD list price, $20/$100/$200), `--bill-day D`, `--top N`, `--format text|md|json`, `--out`, `--redact` (no session titles), `--rates`. The report says what it can't see: the % of the limits used (Claude Code sends that only to the status line) and usage from claude.ai, the apps or other machines. List price is labelled as neither money saved nor a share of the limit.
- `check --all --since` adds up whole sessions by file mtime, so it overstates a period's cost: on one machine, 14 days came to $5,091, while the same 14 days by request time came to $1,410 (old card). Use `plan` for "what did this month cost".

**Rate card refreshed (2026-10-25).** Opus 5.5 ($4 / $20, cache read $0.20) and Sonnet 5.5 (cache read $0.10) get their own rows. Before this they resolved through the `claude-opus-5` / `claude-sonnet-5` prefixes and were priced as Opus 5 / Sonnet 5. On one Max user's Opus-5.5-heavy month that roughly halves the list-price total ($1,390 → $732), mostly from the cache-read rate. Haiku 5.5 is priced by prompt length: an `over: { at: 100000, … }` tier applies to the whole request when input plus cache reads plus cache writes go over 100k. `--rates` files accept `over` too. `requestCost` is exported, and `req.apiError` keeps the record's `error` code.
- `test/claims.test.mjs` read its fixture through `URL.pathname`, which fails on Windows (`C:\C:\…`). It now uses `fileURLToPath`.
- Tests: `test/plan.test.mjs` (10). 186 tests. README, DESIGN.md §22, docs/IT.md §3.

### The status line, `plan --live` and the rate-card check (built locally as "0.12.0")
**`glassbox statusline`: the plan's real limits.** Claude Code gives a status-line command `rate_limits.five_hour` / `seven_day` (`used_percentage` 0–100, `resets_at` in epoch seconds, for subscribers after the first reply), which no transcript ever holds. The status line prints them, `Opus 5.5 · ctx 32% │ 5h 20% · 1h16m left │ week 78% · resets 14:29`, green, yellow and red at 50% and 80% (`--no-color`, `NO_COLOR`). API-key users see "no plan limits". It parses no transcript and always prints a line and exits 0.
- It logs a snapshot `{t, session, model, five, week}` to `~/.claude/glassbox/limits.jsonl` when this session's reading changes, or every 10 minutes if it doesn't. The file is 0600 and rotates to `limits.1.jsonl` at 4 MB.
- `statusline install [--no-color] [--command CMD]` writes `statusLine` to settings.json with a backup. The command is the direct `node ".../bin/glassbox.mjs"` form, because npx is too slow for every refresh. An existing status line is saved and keeps running in front, with its last good line shown if it runs past 2 s (Windows process start can be that slow). `statusline uninstall` restores it.

**`plan --live`.** From the snapshots it reports:
- the latest 5-hour and weekly % with reset times (a window that has reset since is shown as such)
- the **exact** 5-hour windows and weeks (start = `resets_at` − 5 h / 7 days), each with its peak % and the local list price in it
- per session, how far the week and the 5-hour window moved between its first and last reading in each window, labelled "while it ran": other usage counts too

There's no forecast and no tokens-to-% fit. Checked on the development machine: the exact window matched the app's usage card to the second (16:19–21:19), holding $18.87 of local list price at 20%, and the week $420.08 at 78%.

**Rate-card check.** `rateCardCheck()` / `rateCardLine()` in the core flag a model priced through an older version's row (`claude-opus-5-6` by `claude-opus-5`, the 0.10 Opus 5.5 bug), a model with no price, and a built-in card more than 60 days older than the session's last request (`RATES_DATE`; not reported for a `--rates` card). These show in `check` (a line under the cost, `summary.rateCard` in JSON, a note in markdown, also through the Stop hook and the Action) and in `plan`. Rows for `claude-sonnet-4-6` and `claude-sonnet-4-5` (same price as Sonnet 4), so dated Sonnet 4.x ids are exact. `rateKey()` exported.
- **Fix:** a `--rates` row now covers its whole family. Since 0.11 added longer built-in rows, a user's `claude-sonnet-4` row was quietly outbid by the built-in `claude-sonnet-4-5` for `claude-sonnet-4-5-…` ids. Built-in rows that are longer prefixes of a user's row are now dropped unless the user gave them too.
- Tests: `test/statusline.test.mjs` (9), `test/plan.test.mjs` +3 assertions. 195 tests; browser e2e on Edge. README, DESIGN.md §23, docs/IT.md §3.

### The enterprise pack (built locally as "0.13.0")
**The enterprise pack.** What a company's IT and security review asks for before Glassbox goes on developer machines.
- **Bedrock / Vertex pricing.** `normaliseModel()` reads Bedrock ids (`[global.|us.|eu.|apac.|…]anthropic.claude-…-v1:0`) and Vertex ids (`claude-…@date`) onto the same rows. A regional or multi-region endpoint is 1.1× on Claude 4.5 and later (Sonnet 4 / Opus 4.1 and earlier keep one price), taken from the Bedrock id or from `--endpoint global|regional`. `--geo us` is first-party US-only inference (1.1× on 4.6 and later; refused with Bedrock or Vertex). `--platform anthropic|bedrock|vertex`. A `--rates` row the user priced themselves isn't raised again for a regional id. `check` prints and returns (`summary.pricing`) one line saying how the session was priced, and `plan` does the same. The setting rides on the card as a non-enumerable `_pricing`, so the viewer's rate editor never sees it. Exported: `normaliseModel`, `withPricing`, `premiumFor`, `pricingNote`.
- **`fence --markings`.** Export-control and classification markings that reached a transcript:
  - *error:* classification banners, ITAR markings and the ITAR / AECA legend sentences, CUI, DoD distribution statements B–F
  - *warn:* `EXPORT CONTROLLED`, the EAR legend, ECCNs
  - *info:* `EAR99`
  It's opt-in, because prose about export rules is not a spill. The patterns are markings as printed, and like the secret detectors they match after a JSON `\n`. `--markings-file FILE` adds your own (`{ id, pattern, flags?, severity? }`, validated; an empty-matching pattern can't hang the scan). The preview is the marking itself, and the report groups them under "Export-control markings, by how far they spread", separate from secrets. `--shred` never touches them, because removing a marking would leave the controlled text unmarked. On the development machine, 96 files from two days held markings only in the session that wrote these detectors and their tests.
- **Temp-folder policy.** `open` without `--out` obeys `GLASSBOX_TEMP=allow|redact|deny`, read from the environment, then from `env` in Claude Code's managed settings (main file, then drop-ins by name). `redact` (and `open --redact`) embeds a structure-only copy through `core.redact`: «N chars» for every prompt, input, result and text, with tool names, timings and usage kept. `deny` refuses and asks for `--out`. `redactFiles()` exported.
- **`glassbox managed`.** It prints Claude Code managed settings for the hook (`--hook [--feedback] [--context] [--guard] [--fail-on]`), the status line (`--statusline [--no-color]`) and the temp policy (`--temp`). `--install` writes them as `managed-settings.d/glassbox.json` in `C:\Program Files\ClaudeCode`, `/Library/Application Support/ClaudeCode` or `/etc/claude-code`, the paths and drop-in folder read from the 2.1.278 binary. It never edits `managed-settings.json`, takes a backup when replacing its own file, and gives a clear "run as administrator" on EACCES. `--uninstall`, `--dir`, `--out`, `--command`. It warns when the command points into one user's profile. `hookEntries()` is shared with `hook install`.
- **Offline bundle.** `npm run bundle` (`scripts/bundle.mjs`) writes `release/glassbox-trace-<v>/`: the `npm pack` tarball, `glassbox-viewer.html`, `sbom.cdx.json` (CycloneDX 1.5: the package with its SHA-256 and purl, the viewer, and the seven IBM Plex woff2 files embedded in it, OFL-1.1, each hashed; composition *complete*; a serial number derived from the tarball hash; `SOURCE_DATE_EPOCH` for the timestamp), `SHA256SUMS` (checked with both `--verify` and coreutils `sha256sum -c`) and `INSTALL.md`. The tarball came out byte-identical on two runs, and it installed with `npm install --global --offline` into an empty prefix.
- Tests: `test/enterprise.test.mjs` (15). 210 tests. README "In a company", DESIGN.md §24, docs/IT.md §4, §7b, §7c, §8, §10.

### Claims, second calibration (built locally, unreleased)
**The claims ledger, second calibration.** Run over 145 real Claude Code sessions, the local 0.13.0 flagged 254 of 3,184 claims (171 unverified, 83 contradicted), and a hand check found almost all of them were the ledger misreading honest sentences. Four fixes, each with a synthetic test:
- **A failure the agent admits is not a contradiction.** "410 of 412 pass", "410 passed and 2 failed", or "410 pass. The 2 failures are the network tests." are checked against the run's own tally: when it agrees, the claim is *verified*; when it doesn't ("410 of 412" against a run of 409 and 3), it is *contradicted* and the note gives both tallies. A failure admitted only in words ("passes except the clock tests"), in the sentence, the next one or the one before, is *declared*. A sentence that names a count the failing run doesn't carry is about another run (*partial*), so is "my new tests pass" against a suite with unrelated failures, and so is one named check ("the lap check passed") when no FAIL row names it.
- **Every summary in a result counts.** A command that prints PHP's totals and then pytest's has two, and "Python: 64 pass" is judged on the second. A run against the old code followed by one against the new also has two.
- **Background runs.** A `run_in_background` launch is no longer a run (its result only says it started). Its run is the `Read`, `cat` or `TaskOutput` of `tasks/<id>.output` after the `<task-notification>` (or once the output carries `[exited with code N]`); a read before that is a peek at partial output. The notification's exit code rides along.
- **More runner formats.** Python unittest (`Ran 9 tests … OK` / `FAILED (failures=1)`), `gh run view` job lists (`ubuntu-latest / Node 22: success`, either order), `gh pr checks` rows, `48/51 checks pass`, `10 of 10 tests passed`, `ok:42 … 0 failures`, `ALL 19 PASSED`, a self-test's `"passed": 364, "total": 364`, and the count-free `RESULT PASS`, `all passed` and `allPass: true` (also from the browser's `javascript_tool`). "lint clean" is judged on `php -l`, `node --check` and the like. A 7-digit number is a run id, not a count.
- **A red run the agent planted.** A failing run after the claim, or in the same message, doesn't contradict it when the agent says it is deliberate ("against the old code", "with the fix disabled", "to show the check would have caught it"), and a sentence that describes that run ("the two new tests fail against the old code and pass with the fix") is verified.
- Re-run on the same 145 sessions: 169 flags (148 unverified, 21 contradicted), down from 254. The three sentences the hand check found with no receipt behind them are all still flagged. What's left is mostly receipts in earlier turns, headings and quoted drafts read as claims, and evidence the ledger can't see (screenshots, mail headers); those are the next fixes. Details in docs/CLAIMS.md *Calibration*.
- Tests: `test/claims.test.mjs` +4 (24). 214 tests.

### Merging the two lines
- **Claims.** GitHub's 0.11.1 and the local second calibration reworked the same verdict code from 0.10. The local logic is the base (all summaries in a result, background runs, admitted failures checked against the tally, more runner formats, planted red runs); GitHub's rules ride on top: the sentence's own response split into before and after, the confirming check ending at the next edit, `&` background starts and `pytest --co` not being runs, pytest collection errors as failures, and "all" / "green" / "not a single one failed" with any failure staying contradicted. Two of the local readings were wrong and are fixed by GitHub's: "Not one failed." read as one failure, and "The 3 failures from this morning are fixed." read as owning up to three. A sentence that admits the failure in the same breath ("passes except the clock tests") is not caught by the whole-suite rule, and a count of 7+ digits is still an id, not a count. Both suites (24 + 13 cases) pass on the merged code.
- **Big transcripts and the enterprise pack.** `fence --markings` works on segmented (big-file) scans, and segmented `--shred` never touches a marking. `open` refuses a transcript over 64 MB before the temp-folder redaction runs.
- **Memory and `managed`.** `glassbox managed --hook --context` follows 0.12's one-memory default (Stop only); `--memory glassbox` brings back SessionStart, as with `hook install`.
- **Found reviewing the merge** (each a test): GitHub's "fixed / gone" guard, carried into the local tally reader, also caught sentences that say the failures are *not* fixed ("the 2 failures aren't fixed yet") and turned them contradicted — negated forms are now read as still failing; and the plugin's hooks looked only in `settings.json` for a Glassbox hook already installed, never in the managed settings `glassbox managed` writes, so a machine with both would run the guard twice per command and Stop twice per turn — both hooks now read `managed-settings.json` and `managed-settings.d/` too (`src/managed-paths.mjs`, light enough for the guard). A count the run doesn't carry ("All 175 of Bob's fast tests pass." over a run with other counts) is now `partial` — about another run — where both lines said contradicted: GitHub's wider count reader feeds the local rule for it. `scripts/bundle.mjs` quoted the `npm pack` path for Windows' shell on every platform and failed on Linux and macOS; it now quotes only on Windows.
- DESIGN.md: the local §20–22 are now §22–24 (GitHub's §20 is memory, §21 is the road to 90).

## 0.11.1 — 2026-10-25
**Fewer false "contradicted".** A contradicted claim is the worst thing Glassbox prints, so it has to be right. Forty real sessions (207 claims) were run through 0.11.0 and every contradicted row was read against its transcript. Five of seven were wrong, and they are fixed here, each with a test. After the fix, the 207 claims have 2 contradicted rows, and one of them is real. docs/CLAIMS.md has the details (*Calibration*, *Verdicts*).
- **A count with its failures named is true.** "1,043 tests pass, including the two new ones. The 3 failures are the same ones the v3.69 run had" over `1043 passed, 3 failed` is now `verified`, noted *the failures are named in the same message*. The failures count as named when the sentence or the two after it give the same number of failures, called failures, and do not call them fixed or gone. The same count with the failures left out stays `contradicted`, and the note says what was left out. A sentence that speaks for the whole suite ("all", "fully", "green", "not a single one failed") with any failure stays contradicted. "175 of Bob's fast tests pass" and "40/43" now read as counts.
- **Judged as of the sentence.** A test claim is judged on the runs before it plus its confirming check: the runs after it up to the next write to code or tests, or the next shell edit. A red run straight after the sentence still contradicts it; a red run after new tests are written does not. A tool call later in the sentence's own response counts as after it, and those calls no longer use up the window's 12 later calls. A background start (a trailing `&`, `run_in_background`) and a `pytest --co` step are not runs. A pytest collection error (`ERROR collecting`, `Interrupted: 1 error`) is a failure.
- **Ship.** A device write's `"rejected":[]` is not a rejection, and an empty `"written":[]` is not a save. A failed step retried before the sentence, with the same tool and the same ship command, is `unverified`, not `contradicted`. "published" before *lists*, *data*, *rates*, *rules* and similar nouns is an adjective. "Deployed rules to Firestore" is still a ship.
- An independent review tried to make these rules hide real failures, and each case it found is a test. Tests: `test/claims.test.mjs` +13 (204).

## 0.11.0 — 2026-10-10
**Memory: what the next session should know.** `--context` carried one session's findings to the next and forgot the rest — the note was overwritten by every session with findings and deleted after a clean one, so Monday's lesson was gone by Wednesday. The Stop hook now keeps `<project>/.glassbox/memory.json`: a digest of each of the project's last 50 sessions (the first two and last three prompts, the agent's last words in its last three turns, files written, the checks that ran and how the last run of each ended, pushes, publishes and deploys, commit shas and subjects from git's own output, turns, tool calls, cost) and **lessons** — findings counted across sessions by what they are about: `retry-loop · Bash npm test`, `failed-tool · Edit`, `duplicate-subagent-read · docs/ARCHITECTURE.md`, `unverified-claim · test`. Rules the agent can't act on (`slow-model`, `long-generation`, `api-error`, `missing-final-usage`, `orphan-tool`, `idle-cache-expiry`) are not lessons. A lesson stays active while it has fired in the last ten sessions, then retires (and comes back if it fires again).
- **The note.** The SessionStart hook (`startup`, `clear`, `compact`; not `resume` or `fork`) now hands over the five worst active lessons with each rule's "next time" line once, a line per recent session (`2026-10-09 14:02 · a1b2c3d4 · "fix the login redirect" — wrote src/auth.js · ran npm test (passed, last of 3) · committed 1a2b3c4 "fix: …" · pushed`), and the previous session's notes — shortened to their header, the findings that didn't make the list and the agent's own answer when lessons are shown, as they are otherwise. At most 8,000 characters (Claude Code caps `additionalContext` at 10,000). On the transcript of the session that built it, 0.10.1 handed the next session 3,928 characters — eight findings with their evidence, among them a slow API response and the call still running when the hook read the transcript; 0.11 hands over 2,462: the five lessons, a line for the session, and the previous session's header.
- **Told, came back.** A session whose note carried a lesson is counted as told (at its start, never on compaction); if the lesson fires anyway, it came back. `glassbox memory` reports both per lesson. An observation, not an experiment.
- **Secrets never reach memory.** `maskSecrets()` (new in `src/fence.mjs`) runs every `fence` detector over what is written and replaces values with `[FENCED:<rule>]` — in `memory.json`, in `last-session.md` (which 0.10 wrote unmasked) and in the agent's appended reply. Both files are created owner-only (0600); writes go through a temp file and a rename; a ledger that doesn't parse starts over instead of failing the hook.
**`glassbox recall [words]`** — search a project's past sessions: prompts, commit subjects, the agent's last words, files written, checks run, lesson keys; every word must match, a quoted phrase is one term, best match first, up to five snippets per session (*asked*, *said*, *wrote*, *ran*, *commit*). It reads the transcripts still on disk and, for sessions Claude Code has since deleted (after `cleanupPeriodDays`, 30 by default), the ledger. - **Streamed usage.** Subagent transcripts rewrite `output_tokens` on every block record of a response; Glassbox kept the first (often 2–8 tokens). It now keeps the largest value per field, which fixes output, cost, tok/s and most `slow-model` warnings.

- Blocking `TaskOutput` polls roll up into one info `slow-tool` per background task and are not a `retry-loop`; identical findings print once with `×N` in `check`, the hook summary and `compare`.
